## 1. 基本方針

- **関数・定数・クラス・型を宣言する場合には必ず JSDoc を記載すること。**
- **コメントは明確かつ簡潔に記述すること。**
- すべてのコメントは **日本語（Ja-JP）** で統一すること。
- **型は書かないこと。**`@type` / `@param {型}` / `@returns {型}` のように型を繰り返してはいけません。TypeScript の注釈が唯一の定義元です

> **なぜ型を書かないのか。**型を 2 箇所に書くと必ずずれます。本プロジェクトは実際に、
> 型定義と実装が食い違った状態（`_kept` と `_keptEntries`、`settled` の不正値）を抱えたまま長期間気づけませんでした。
> **JSDoc は「何のためにあるか」を書く場所であり、「何であるか」は TypeScript が書きます。**

---

## 2. コメントの形式

### 2-1. 1 行目の形式

コメントの 1 行目は `/** 名前 - 説明` の形式で始めること。1 行目と続く `@` コメントの間に空行を **入れない** こと。

```ts
/**
 * PI - 円周率
 */
const PI = 3.14159;
```

### 2-2. 記載順序

`@` コメントは、**型や説明を必要としない「属性コメント」**（`@internal` / `@deprecated` / `@constant` など）を先に、
**説明を伴う「注釈コメント」**（`@param` / `@returns` / `@throws` / `@example`）を後に記載します。

```ts
/**
 * API_BASE_URL - API のベース URL
 * @constant
 */
const API_BASE_URL = 'https://api.example.com';
```

## 3. `@internal` — 公開契約の境界（重要）

**本プロジェクトで最も重要なタグです。**

ビルド時の型定義生成は `stripInternal: true` で行われるため、**`@internal` を付けたメンバーは公開される型定義から取り除かれます。**
つまりこのタグは、**何が利用者への約束で、何がそうでないかを決めます。**

```ts
export interface LayergeStore {
    /** 現在のモード */
    mode: LayergeMode;

    /** @internal */
    _closeTop?: (options?: LayergeCloseOptions) => void;
}
```

守るべきこと。

- **内部専用のメンバー・型には必ず `@internal` を付けること。**付け忘れは内部実装の公開を意味し、利用者が依存し始めます
- **`_` 接頭辞は「内部のつもり」を示すだけで、何も強制しません。**実際に公開面から除くのは `@internal` です。両方を付けてください
- **公開するつもりのメンバーに `@internal` を付けないこと。**公開型から静かに消え、利用者のコードが壊れます
- 内部型（`PresenterHandleInternal` など）は `layerge/index.ts` から**再エクスポートしないこと**

> 公開面に何が出ているかは `pnpm build` 後の `dist/types/index.d.ts` で確認できます。**迷ったら生成物を見てください。**

## 4. 定数

- 定数であることを明示するため、`@constant` を記載すること
- **`@type` は記載しないこと。**型は TypeScript が持ちます

```ts
/**
 * SUPPORTED_LANGUAGES - サポートされている言語のリスト
 * @constant
 */
const SUPPORTED_LANGUAGES: readonly string[] = ['en', 'ja', 'fr'];
```

## 5. 関数

### 5-1. 必須ルール

- **`@param` と `@returns` に「説明」を記載すること。型は書きません**
- 関数が明示的にエラーをスローする場合は `@throws` も記載すること
- 引数の意味が名前だけで自明な場合でも、**単位・前提・副作用**があれば必ず書くこと

```ts
/**
 * registerUser - ユーザーを登録します
 * @param username - 登録するユーザー名
 * @param age - 登録するユーザーの年齢
 * @throws age が 18 未満の場合にエラーをスローします
 * @returns 登録されたユーザー情報
 */
const registerUser = (username: string = 'Guest', age: number): User => {
    if (age < 18) {
        throw new Error('ユーザーは18歳以上である必要があります。');
    }

    return {username, age};
};
```

### 5-2. 書くべきこと・書かなくてよいこと

| 内容 | 扱い |
|---|---|
| 引数・戻り値の**型** | **書かない**（TypeScript が持つ） |
| 引数の**意味・単位・前提** | **書く** |
| 省略時の**既定値の意味** | **書く**（値自体は TypeScript に出る） |
| **副作用**（状態変更・DOM 操作・非同期の確定タイミング） | **書く** |
| スローする条件 | **書く**（`@throws`） |
| 実装の手順をなぞった説明 | 書かない。コードを読めば分かります |

> **「何をするか」ではなく「なぜ・どういう前提で」を書いてください。**

## 6. クラス

TypeScript が `private` / `readonly` / `static` / `implements` を言語機能として持つため、
旧版にあった `@private` / `@static` / `@property` / `@implements` の記載義務は**廃止します。**

残すのは次の 2 つです。

- クラス全体の役割を説明する JSDoc
- メソッド・アクセサに対する `@param` / `@returns` / `@throws` の**説明**

```ts
/**
 * User - ユーザーを表します
 */
class User {
    /** アクティブかどうか */
    #isActive = true;

    /**
     * getInfo - 名前と年齢を人間可読な形で返します
     * @returns 表示用の文字列
     */
    getInfo(): string {
        return `${this.name} is ${this.age} years old.`;
    }
}
```

## 7. 汎用JSDocコメントルール

- 必須としないが、必要に応じて汎用コメントを適切に使用しコードの意図を明確に伝えるようにすること

| コメント        | 概要                                            | 利用ケース                                                 | 使用例                                                                            |
|------------------|------------------------------------------------|------------------------------------------------------------|-----------------------------------------------------------------------------------|
| **`@default`**     | プロパティのデフォルト値を記載します。       | オプション引数やプロパティの初期値を示したい場合。         | `@default 10`                                                                     |
| **`@deprecated`**  | 非推奨であることを示します。                 | 使用を避けるべきメソッドやクラスを明示したい場合。         | `@deprecated このメソッドは廃止予定です。代わりに newMethod を使用してください。` |
| **`@description`** | 詳細な説明を記載します。                     | 関数やクラス、プロパティの具体的な動作を補足する場合。     | `@description このメソッドは指定された値を計算します。`                           |
| **`@example`**     | 使用例を示します。                           | 関数やクラスの使用方法を明確に伝えたい場合。               | `@example calculate(5, 10); // 結果は 50`                                         |
| **`@ignore`**      | ドキュメント生成時に特定の要素を無視します。 | 特定のプロパティやメソッドを非公開にしたい場合。           | `@ignore このメソッドは内部利用専用です。`                                        |
| **`@link`**        | 外部リンクや参照箇所を示します。             | メソッドやクラス、プロパティの詳細を別途参照させたい場合。 | `@link https://example.com API ドキュメント`                                      |
| **`@see`**         | 関連情報や参考資料へのリンクを示します。     | 詳細な情報や関連する仕様を示したい場合。                   | `@see {@link https://developer.mozilla.org/\| MDN ドキュメント}`                  |


## 8. 通常コメントルール

### 8-1. 基本方針

- if/else文および三項演算子には必ずコメントを記載すること
- アノテーションコメントを積極的に活用し、コードの中に次のタスクや現在の問題点を明確に記載すること

#### if/else文のコメントルール

- if/else文は、各条件の直前に「条件分岐についての説明」をコメントとして記載し、分岐の意図を明確にする

```javascript
// システムが正常動作している場合、正常動作中のログを記録
if (systemStatus === 'operational') {
    logStatus('System operational');

// システムが警告状態の場合、警告を通知
} else if (systemStatus === 'warning') {
    notifyAdmin('System warning');

// システムがエラー状態の場合、エラーを記録し緊急通知を送信
} else {
    alertCriticalError('System error');
}
```

#### 三項演算子のコメントルール

- 三項演算子には、条件と処理内容を簡潔に説明するコメントを記載すること

```javascript
// ユーザーが管理者の場合は管理パネル、それ以外は通常のダッシュボードを表示
const page = isAdmin ? 'AdminPanel' : 'Dashboard';
```

### 8-2. アノテーションコメントの活用

アノテーションコメントを活用し、コードの中に次のタスクや現在の問題点を明確に記載すること
特定の問題や要件を明記することで、開発者間の認識齟齬を防ぐ目的があります

| アノテーション | 説明                                                                           | 使用例                                                    |
|----------------|--------------------------------------------------------------------------------|-----------------------------------------------------------|
| TODO           | 将来的なタスクや改善点を記載します。                                           | `// TODO: 新しいAPIエンドポイントを実装する`              |
| FIXME          | 現在のコードに問題があり、修正が必要であることを記載します。                   | `// FIXME: 非推奨のメソッドを使用しているため要修正`      |
| NOTE           | 特定のコードに関する補足情報や注意点を記載します。                             | `// NOTE: このアルゴリズムは特定の条件下でのみ動作します` |
| HACK           | 一時的な解決策やトリッキーな実装について記載します。                           | `// HACK: パフォーマンスの問題を回避するため暫定対応`     |
| REVIEW         | レビューが必要な箇所や、他の開発者の確認を求める場合に記載します。             | `// REVIEW: このロジックの最適化について意見を求めたい`   |
| DEPRECATED     | 非推奨であることを記載します。将来的に削除される可能性があることを明示します。 | `// DEPRECATED: この関数は廃止予定。代わりに新関数を使用` |

#### 記載例

```javascript
// TODO: APIのエラーハンドリングを追加する
fetchData().catch(handleError);

// FIXME: メモリリークの可能性があるため、この部分をリファクタリングする必要あり
const data = loadLargeDataset();

// NOTE: このアルゴリズムは特定の条件下でのみ動作します
const result = customAlgorithm(inputData);

// HACK: パフォーマンスの問題を回避するため暫定対応
const optimizedResult = temporaryFixForPerformance(inputData);

// REVIEW: このロジックの最適化について意見を求めたい
const finalValue = complexCalculation(values);

// DEPRECATED: この関数は廃止予定。代わりに新関数を使用
oldFunction();
```
