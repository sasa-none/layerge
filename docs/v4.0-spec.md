# Layerge v4.0 Spec

Layerge v4.0 is **not** a feature-addition release.
It is an **internal cleanup / normalization** phase that keeps v3’s public contract intact while improving debuggability and long-term safety.

## 0. Definition of v4.0

v4.0 must achieve the following **without expanding the public surface**:

- Normalize the internal **Outcome** model
- Freeze the meaning of `aborted/blocked/superseded` to prevent misinterpretation
- Introduce **DecisionTrace** (dev-only) so “nothing happened” can be explained
- Clarify environment differences (SSR / multi-tab / router differences) strongly and explicitly
- Prove (and test) that long-running usage does not cause **leaks** or **unbounded growth**

---

## 1. Non‑negotiable guardrails (inherited from v3.x)

These constraints are frozen in v4.0:

- Do **not** add public state (e.g. no new `EntryContext` fields)
- Layerge does **not** guarantee or provide UI (no confirm/fallback UI in the library)
- Do **not** break latest-wins convergence
- Do **not** add APIs “because convenient” (v4.0 is “no public API additions” in principle)
- Exceptions must not be “thrown at users” as a contract; use an observation / convergence model

---

## 2. Frozen v4.0 spec

### 2‑1. A: Internal Outcome normalization (no public expansion)

Public (user-facing) status remains v3 compatible and stays at **4** values:

- `completed | aborted | failed | superseded`

Internal uses a normalized Outcome with **two fixed axes**:

- `stage: open | navigate | close | restore`
- `status: completed | failed | aborted | superseded | blocked`

Projection rules (internal -> public):

- `blocked` **must be folded into public `aborted`**
- Other statuses project 1:1

Why: expanding public statuses tends to trigger hook expansion and contract bloat.

#### Notes for implementers

- Internal Outcome is for Layerge’s own reasoning / logging / tests.
- The public result type must remain unchanged (compat).

---

### 2‑2. B: Frozen meaning of `aborted/blocked/superseded`

These definitions are frozen in v4.0:

- `blocked`: canceled by `controlledHooks` (`beforeOpen/beforeNavigate/beforeClose`)
- `aborted`: canceled by leave guard / confirm UI (e.g. user cancel)
- `superseded`: lost due to latest-wins concurrency and converged

Additional notes:

- Do **not** add `meta.by = latestWins` (too redundant / different flavor)
- If additional clarification is needed, a dev-only reference like `supersededBy*` (traceId) may exist internally.

---

### 2‑3. C: DecisionTrace (dev-only, structured events)

DecisionTrace is **not** an exception stack trace.
It is a structured “decision ledger” for explaining why an operation converged to “no-op”.

**Three logging layers (conceptual):**

1. Outcome summary (one line)
2. DecisionTrace (dev-only, opt-in)
3. Error stack trace (only when `failed`)

**All operations must carry `traceId`**, so stack traces can be correlated to DecisionTrace.

#### Event types (fixed and small)

DecisionTrace is a sequence of structured events.
Event types are fixed to avoid proliferation:

- `start`
- `resolveTarget`
- `validate`
- `runHook`
- `applyRouter`
- `latestWins`
- `commitLeaving`
- `settle`
- `log`
- `error`

#### Output levels (dev-only opt-in)

- `off` (default)
- `on-failure`
- `on-unexpected` (blocked/aborted/superseded/failed)
- `verbose` (all events)

Guardrails:

- **prod must never emit verbose**
- Do not log secrets: URL/query/hash/user data must be **sanitized**

---

### 2‑4. D: Environment differences (support matrix)

This support matrix is **fixed** and must not be removed:

| Topic | Contract |
|---|---|
| SSR in progress | out of scope (no-op + dev warning; must not crash) |
| After hydration | guaranteed |
| Same-tab concurrency | guaranteed (latest-wins) |
| Multi-tab | undefined (not guaranteed; must not crash) |
| Router differences | partially guaranteed (do not absorb; converge as failed + observable outcome) |
| Browser events | out of scope (no UI; library does not own UX) |

#### Use cases (8 short entries)

1) **User taps open twice quickly**: first operation may be `superseded`; trace explains which won.

2) **controlledHooks blocks open**: internal `blocked` -> public `aborted`; trace shows `runHook` => `blocked`.

3) **Leave guard cancels close**: `aborted`; trace shows guard result.

4) **Navigate target resolves to same URL**: should converge without history bloat; trace shows `resolveTarget` + no-op path.

5) **Router mismatch (unsupported behavior)**: must not crash; converge as `failed` with observable reason and trace.

6) **SSR attempt to open**: no-op (dev warning); must not crash.

7) **Multi-tab race**: contract is undefined; still must not crash; trace is local to tab.

8) **Long session with repeated open/close**: must not leak; metrics must return to baseline.

---

### 2‑5. E: Long-term operations (no leaks, no unbounded growth)

The two highest priority incidents are:

1. **Leaks** (leftover entries / listeners)
2. **Unbounded growth** (trace or internal lists growing without bound)

#### E‑1: Leak‑free invariant

After an operation settles, the following must not retain:

- `EntryRegistry`
- `leaving`
- `listeners`

Dev-only observation points (not public API):

- `entryCount`
- `leavingCount`
- `beforeunloadEnabled` (`true/false`)

Recommended verification:

- After many iterations, all return to baseline:

  - `entryCount == 0`
  - `leavingCount == 0`
  - `beforeunloadEnabled == false`

#### E‑2: Bounded trace storage

DecisionTrace must be bounded by count limits (ring buffers):

- recommended: `maxTraces = 50`
- recommended: `maxEventsPerTrace = 100`

---

## 3. Where the v4.0 internals live (implementation hint)

v4.0 does not add public API.
Internal-only modules are kept under `layerge/internals/` and are not exported:

- `layerge/internals/outcome.js`
- `layerge/internals/decisionTrace.js`
- `layerge/internals/devMetrics.js`

This layout is intentional to avoid encouraging external usage.

---

## 4. How to use DecisionTrace (dev only)

DecisionTrace is opt-in.
The implementation reads level from dev-only configuration mechanisms (example):

- `globalThis.__LAYERGE_DECISION_TRACE_LEVEL = "on-unexpected"`
- `process.env.LAYERGE_DECISION_TRACE_LEVEL = "on-unexpected"`
- `import.meta.env.VITE_LAYERGE_DECISION_TRACE_LEVEL = "on-unexpected"`

Recommended defaults:

- local dev: `on-unexpected`
- debugging a complex issue: `verbose` (dev only)
- production: `off` (enforced)

---

## 5. Compatibility statement

- Public statuses remain: `completed | aborted | failed | superseded`
- No public state expansion (`EntryContext` stays minimal)
- No new public APIs are introduced in v4.0
- Any new debug/inspection capability remains **dev-only** and **internal**
